## 介绍

Nuxt SEO v5 把每个子模块都提升到了新的主版本（OG Image 除外，它仍停留在 v6）。贯穿始终的线索是 **Site Config v4** 依赖；先处理这些变更，其余迁移就会更顺畅。

逐步升级说明见 [v4 到 v5 迁移指南](/docs/nuxt-seo/migration-guide/v4-to-v5)。

## 🛠️ DevTools 统一

v5 最大的变化是：每个 Nuxt SEO 模块现在都通过我们新的 **共享 DevTools 层**（`nuxtseo-layer-devtools`）共享同一套 DevTools 基础。

以前每个模块都有自己的 DevTools 客户端，布局、模式和能力都不一致。在 v5 中，所有 DevTools 客户端都扩展一个公共 Nuxt 层，它提供：

- **一致的布局和导航**，覆盖每个模块，并带有模块切换器以便在它们之间跳转
- **设置检查清单**，会校验所有已安装模块的配置，并标出必需和推荐操作
- 每个模块都内置 **故障排查**、更新提示和生产模式预览

SEO Utils 第一次有了全新的 DevTools 客户端，Robots、Sitemap、Schema.org 和 Link Checker 的 DevTools 也都已改用共享层。

![Nuxt SEO v5 设置检查清单，展示 Site Config、Robots 和 Sitemap 的模块配置提示](/images/nuxt-seo/releases/v5.png)

## 🔗 ESLint 链接检查

Nuxt Link Checker v5 提供 [ESLint](https://eslint.org) 集成，并对 `@nuxt/eslint` 零配置支持：

- `link-checker/valid-route`（error）：校验相对 URL 是否匹配已知路由，并给出「你是不是想写？」建议
- `link-checker/valid-sitemap-link`（warn）：检查 URL 是否存在于站点地图中
- 扫描 Vue 模板、TS/JS（`navigateTo`{lang="ts"}、`router.push`{lang="ts"}）和 Markdown 链接

如果你使用 `@nuxt/eslint`，规则会自动注册。否则请手动添加：

```ts [eslint.config.ts]
import linkChecker from 'nuxt-link-checker/eslint'

export default [
  linkChecker,
]
```

当链接不匹配任何路由时的示例输出：

```text
error  Link "/abut" does not match any known route. Did you mean "/about"?  link-checker/valid-route
```

## 📱 社交分享链接

SEO Utils v8 引入了 `useShareLinks()`{lang="ts"}，这是一个用于生成社交分享 URL（Twitter、Facebook、LinkedIn、WhatsApp、Telegram、Reddit、Pinterest、Email）的组合式 API，并内置 UTM 追踪。

```vue
<script setup lang="ts">
const links = useShareLinks({
  title: 'Check out Nuxt SEO v5!',
  twitter: { via: 'harlodev', hashtags: ['nuxt', 'seo'] },
  utm: { source: 'auto', campaign: 'v5-launch' },
})
</script>

<template>
  <nav>
    <a :href="links.twitter">Share on X</a>
    <a :href="links.linkedin">Share on LinkedIn</a>
    <a :href="links.reddit">Share on Reddit</a>
  </nav>
</template>
```

该组合式 API 会自动解析当前路由的规范 URL，并追加各平台的 UTM 参数。传入 `utm: false` 可以完全禁用追踪。

## 🖼️ Favicon 生成 CLI

新的 `nuxt-seo-utils icons` CLI 命令可以从一张源图生成所有 favicon 和图标变体：

```bash
npx nuxt-seo-utils icons --source logo.svg
```

这会从 `public/` 中的源图生成 `favicon.ico`、`apple-touch-icon.png`（180x180），以及 16、32、192 和 512px 的 PNG 图标。需要把 `sharp` 作为开发依赖。

## ⚡ 内联压缩

SEO Utils v8 会自动压缩通过 `useHead`{lang="ts"} 注入的内联脚本和样式。

**之前**（你写的内容）：

```ts
useHead({
  script: [{
    innerHTML: `
      // Track page view
      window.dataLayer = window.dataLayer || [];
      window.dataLayer.push({
        'event': 'page_view',
        'page_path': window.location.pathname
      });
    `,
  }],
  style: [{
    innerHTML: `
      /* Critical above-the-fold styles */
      .hero {
        display: flex;
        align-items: center;
        justify-content: center;
        min-height: 100vh;
      }
    `,
  }],
})
```

**之后**（渲染出的 HTML）：

```html
<script>window.dataLayer=window.dataLayer||[];window.dataLayer.push({event:"page_view",page_path:window.location.pathname});</script>
<style>.hero{display:flex;align-items:center;justify-content:center;min-height:100vh}</style>
```

## 📄 `definePageMeta` 中的 Sitemap 配置

Sitemap v8 允许你直接在 `definePageMeta`{lang="ts"} 中配置 sitemap 选项：

```vue
<script setup lang="ts">
definePageMeta({
  sitemap: {
    changefreq: 'daily',
    priority: 0.8,
  },
})
</script>
```

## 🌐 i18n 多站点地图改进

使用 i18n 多站点地图模式时，自定义站点地图现在会按语言自动扩展。以前你必须为每种语言手动定义站点地图。现在任何带 `includeAppSources: true` 的站点地图都会自动扩展：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  sitemap: {
    sitemaps: {
      // 自动扩展为 "en-pages"、"fr-pages" 等
      pages: { includeAppSources: true },
      // 没有 includeAppSources 的静态站点地图保持原样
      external: { urls: ['https://example.com/extra'] },
    },
  },
})
```

## ⚠️ 破坏性变更

所有模块现在都依赖 **Site Config v4**，它移除了隐式站点名称推断、旧的 `site*` runtime config 键，以及若干已弃用的服务端 API。若干 Content v3 组合式 API 也已重命名（例如 `asSitemapCollection()`{lang="ts"} → `defineSitemapSchema()`{lang="ts"}）。

完整破坏性变更列表及处理方法见 [迁移指南](/docs/nuxt-seo/migration-guide/v4-to-v5)。

## 🐞 缺陷修复

### 已修复 SSR 内存泄漏

- **Schema.org**：响应式作用域未被释放
- **Site Config**：i18n 插件中的 computed refs

### i18n 修复

- Sitemap：多站点地图重定向中的 base URL、带 base URL/i18n 前缀的 exclude 过滤器、尊重 `autoI18n: false`{lang="ts"}
- SEO Utils：从翻译键解析回退页面标题

### 其他修复

- Schema.org：`@id` URL 现在会尊重 `app.baseURL`，computed refs 中保留 Nuxt 上下文
- Robots：`skipSiteIndexable` 现在会跳过 `Disallow: /` 规则，路由规则增加空值保护
- SEO Utils：错误页会保留用户定义的标题，`useServerSeoMeta`{lang="ts"} 优先于站点默认值
- Sitemap：分块站点地图的路径解析、Content v3 `.navigation` 路径过滤
- Link Checker：在 `excludeLinks` 中序列化 RegExp，以便客户端过滤
