## 故障排查 FAQ

### 我应该使用 @nuxtjs/seo 还是单独安装模块？

`@nuxtjs/seo` 是一个别名，会一次安装全部 6 个模块。它不包含额外逻辑。无论哪种方式，你得到的模块、功能和配置选项都完全相同。

为了方便请使用 `@nuxtjs/seo`。如果你只需要其中几个，或想自己锁定版本，再单独安装模块。

更多细节见 [介绍](/docs/nuxt-seo/getting-started/introduction#the-nuxtjsseo-module)。

**可以单独使用这些模块吗？** 可以！Nuxt SEO 的设计就是灵活的，你可以按自己的方式使用。

**需要单独安装 nuxt-site-config 吗？** 不需要。安装任意 Nuxt SEO 模块时（无论通过 `@nuxtjs/seo` 还是单独安装）都会自动安装 `nuxt-site-config`。你永远不需要把它加到 `modules` 数组里。

**如何把 Nuxt Content 和多个 SEO 模块一起用？** 在 `content.config.ts` 中使用每个模块的 `defineXxxSchema()`{lang="ts"} 函数。只加入你实际使用的模块对应的 schema。

完整设置见 [Nuxt Content 指南](/docs/nuxt-seo/guides/nuxt-content)。

### 为什么生产构建体积增加这么多？

服务端功能会给生产构建增加 2-5MB，但不会影响客户端运行时性能，因为大部分模块逻辑都在服务端运行。

如果生产构建体积是问题，你可以 [禁用不需要的模块](/docs/nuxt-seo/guides/debugging-modules#disabling-modules)。

如果在 serverless 环境中使用 Nuxt SEO，你可能希望把 worker 控制在 1MB 以内。对 worker 体积贡献最大的模块是 `nuxt-og-image`。

::warning
如果目标是小于 1MB 的 worker（Cloudflare Workers 免费套餐），请禁用 nuxt-og-image，或切换到 Zero Runtime 模式以保持在体积限制内。
::

可选方案：

1. 禁用它：`ogImage: { enabled: false }`
2. 使用 [Zero Runtime](/docs/og-image/guides/zero-runtime) 模式（构建时生成）

### Nuxt SEO Kit 去哪了？

Nuxt SEO Kit 模块是 Nuxt SEO 的最初版本。

虽然对部分用户来说它总体工作得不错，但它只适用于服务端生成的 Nuxt 站点，功能集也更受限。

它已被弃用，由新的 Nuxt SEO 模块取代。

更多信息见 [迁移指南](/docs/nuxt-seo/migration-guide/nuxt-seo-kit)。
