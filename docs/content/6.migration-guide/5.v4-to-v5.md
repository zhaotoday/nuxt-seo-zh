## 介绍

Nuxt SEO v5 把每个子模块都提升到了新的主版本（OG Image 除外，它仍停留在 v6）。完整变更列表见 [v5 发行说明](/docs/nuxt-seo/releases/v5)。

| 模块 | v4 | v5 |
|--------|----|----|
| `nuxt-site-config` | v3 | [**v4**](https://github.com/harlan-zw/nuxt-site-config/releases/tag/v4.0.0) |
| `nuxt-seo-utils` | v7 | [**v8**](https://github.com/harlan-zw/nuxt-seo-utils/releases/tag/v8.0.0) |
| `@nuxtjs/sitemap` | v7 | [**v8**](https://github.com/nuxt-modules/sitemap/releases/tag/v8.0.0) |
| `@nuxtjs/robots` | v5 | [**v6**](https://github.com/nuxt-modules/robots/releases/tag/v6.0.0) |
| `nuxt-schema-org` | v5 | [**v6**](https://github.com/harlan-zw/nuxt-schema-org/releases/tag/v6.0.0) |
| `nuxt-link-checker` | v4 | [**v5**](https://github.com/harlan-zw/nuxt-link-checker/releases/tag/v5.0.0) |
| `nuxt-og-image` | v6 | [v6.2.0](https://github.com/nuxt-modules/og-image/releases/tag/v6.2.0) |

## 第 1 步：更新 Site Config

Site Config v4 是影响最大的变更，因为每个模块都依赖它。

### 显式设置 `site.name`

站点名称不再从 `package.json` 或目录名推断。请把它加到 `nuxt.config`：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  site: {
    name: 'My Site',
  },
})
```

### 移除旧的 runtime config 键

`siteUrl`、`siteName` 和 `siteDescription` runtime config 键已不再支持。请迁移到 `site` 对象：

```diff [nuxt.config.ts]
export default defineNuxtConfig({
- runtimeConfig: {
-   public: {
-     siteUrl: 'https://example.com',
-     siteName: 'My Site',
-   }
- },
+ site: {
+   url: 'https://example.com',
+   name: 'My Site',
+ },
})
```

### 更新服务端 API

- `useSiteConfig()`{lang="ts"} → `getSiteConfig(event)`{lang="ts"}
- `getSiteIndexable()`{lang="ts"} → `getSiteConfig(event).indexable`
- `SiteConfig` 类型 → `SiteConfigResolved`
- `#internal/nuxt-site-config` 导入 → 使用来自 `nuxt-site-config` 的具名导入

## 第 2 步：更新 Content v3 集合

如果你使用 `@nuxt/content` v3，集合 API 有显著变化。

### 替换 `asSeoCollection()`{lang="ts"}

来自 `@nuxtjs/seo/content` 的 `asSeoCollection()`{lang="ts"} 包装器已弃用。请改成导入各模块的 `defineXxxSchema()`{lang="ts"} 函数，并直接在集合 schema 中组合它们。

```diff [content.config.ts]
- import { asSeoCollection } from '@nuxtjs/seo/content'
+ import { defineRobotsSchema } from '@nuxtjs/robots/content'
+ import { defineSitemapSchema } from '@nuxtjs/sitemap/content'
+ import { defineOgImageSchema } from 'nuxt-og-image/content'
+ import { defineSchemaOrgSchema } from 'nuxt-schema-org/content'
+ import { z } from 'zod'

export default defineContentConfig({
  collections: {
    content: defineCollection(
-     asSeoCollection({
-       type: 'page',
-       source: '**/*.md',
-     }),
+     {
+       type: 'page',
+       source: '**/*.md',
+       schema: z.object({
+         robots: defineRobotsSchema(),
+         sitemap: defineSitemapSchema(),
+         ogImage: defineOgImageSchema(),
+         schemaOrg: defineSchemaOrgSchema(),
+       }),
+     },
    ),
  },
})
```

::tip
由于你使用的是 `@nuxtjs/seo` 元模块，可以从 `@nuxtjs/seo/content` 一行导入全部四个 `defineXxxSchema()`{lang="ts"} 函数，避免直接从各个模块导入：

```ts [content.config.ts]
import { defineOgImageSchema, defineRobotsSchema, defineSchemaOrgSchema, defineSitemapSchema } from '@nuxtjs/seo/content'
```
::

你只需要加入实际使用的模块对应的 schema。例如，如果只用 sitemap 和 robots：

```ts [content.config.ts]
import { defineCollection, defineContentConfig } from '@nuxt/content'
import { defineRobotsSchema } from '@nuxtjs/robots/content'
import { defineSitemapSchema } from '@nuxtjs/sitemap/content'
import { z } from 'zod'

export default defineContentConfig({
  collections: {
    content: defineCollection({
      type: 'page',
      source: '**/*.md',
      schema: z.object({
        robots: defineRobotsSchema(),
        sitemap: defineSitemapSchema(),
      }),
    }),
  },
})
```

### 替换各个 `asXxxCollection()`{lang="ts"} 函数

各模块自己的集合包装器也已弃用：

| 旧 | 新 |
|-----|-----|
| `asSeoCollection()`{lang="ts"} | 组合各个 schema（见上文） |
| `asRobotsCollection()`{lang="ts"} | `defineRobotsSchema()`{lang="ts"} |
| `asSitemapCollection()`{lang="ts"} | `defineSitemapSchema()`{lang="ts"} |
| `asOgImageCollection()`{lang="ts"} | `defineOgImageSchema()`{lang="ts"} |
| `asSchemaOrgCollection()`{lang="ts"} | `defineSchemaOrgSchema()`{lang="ts"} |

### 确保模块顺序正确

在 modules 数组中把 `@nuxtjs/seo` 放在 `@nuxt/content` 之前：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: [
    '@nuxtjs/seo',
    '@nuxt/content', // 必须在 @nuxtjs/seo 之后
  ],
})
```

## 第 3 步：更新 Sitemap 配置

### `definePageMeta` 中的 sitemap 选项

Sitemap v8 允许你直接在 `definePageMeta`{lang="ts"} 中配置 sitemap 选项。如果你之前用路由规则或其他变通方法做按页 sitemap 配置，现在可以简化：

```vue
<script setup lang="ts">
definePageMeta({
  sitemap: {
    changefreq: 'daily',
    priority: 0.8,
  },
})
</script>
```

### i18n 多站点地图自动扩展

带 `includeAppSources: true` 的自定义站点地图现在会按语言自动扩展。你不再需要为每种语言手动定义站点地图：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  sitemap: {
    sitemaps: {
      // 自动扩展为 "en-pages"、"fr-pages" 等
      pages: { includeAppSources: true },
    },
  },
})
```

运行开发服务器，检查是否有警告或错误。调试生产端点可以帮助验证配置：

- Sitemap: `/__sitemap__/debug-production.json`
- SEO Utils: `/__nuxt-seo-utils`
