- 包名从 `nuxt-seo-kit` 改为 `@nuxtjs/seo`
- `<SeoKit>`{lang="html"} 和 `useSeoKit()`{lang="ts"} 已移除，功能现在是自动的
- 站点配置从 `runtimeConfig.public` 移到 `site` 键
::

## 模块重命名

v2 通过重命名为 Nuxt SEO，明确了模块名称和范围。

- 1.* - Nuxt SEO Kit `nuxt-seo-kit`（Nuxt Layer）
- 2.x - Nuxt SEO `@nuxtjs/seo`（Nuxt Module）

v2 允许你在运行时使用所有 SEO 模块，不再要求预渲染。它也带来了更好的 i18n 兼容性。

重命名是为了给 Nuxt SEO 生态提供更好的基础，也让 layer → module 的变化更明显。

::code-group

```sh [pnpm]
# 移除 nuxt-seo-kit
pnpm remove nuxt-seo-kit && pnpm i -D @nuxtjs/seo
```

```bash [yarn]
yarn remove nuxt-seo-kit && yarn add -D @nuxtjs/seo
```

```bash [npm]
npm remove nuxt-seo-kit && npm install -D @nuxtjs/seo
```

::

```diff [nuxt.config.ts]
export default defineNuxtConfig({
-  extends: ['nuxt-seo-kit'],
  modules: [
+  '@nuxtjs/seo',
  ]
})
```

## 破坏性变更

::warning
我们移除了 `<SeoKit>`{lang="html"} 组件和 `useSeoKit()`{lang="ts"} 组合式 API。请从代码中删除它们；现在由插件自动处理这些功能。
::

**`<SeoKit>`{lang="html"}、`useSeoKit()`{lang="ts"} 已移除**：这些 API 会为你设置所有默认 meta 和模块配置。

在 v2 中它们不再需要，因为功能已移到插件中。

```diff
<template>
-  <SeoKit />
</template>
```

```diff
<script setup>
-  useSeoKit()
</script>
```

如果想退出这些 v2 配置，可以把 [automaticDefaults](/docs/seo-utils/api/config#automaticdefaults) 设为 `false`。

## Site Config 变更

在 v1 中，站点配置通过 runtime config 设置。在 v2 中，我们有一个专门处理这些配置的模块，叫做 [nuxt-site-config](/docs/site-config/getting-started/introduction)。

改成模块是为了在运行时更灵活地更改站点配置。

如果你之前在 `runtimeConfig` 中指定了任何静态配置，现在建议把它移到 `site` 键。

::code-group

```ts [v1]
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      // 你可以移除环境变量，它们会自动设置
      siteUrl: process.env.NUXT_PUBLIC_SITE_URL,
      siteName: 'My App'
    }
  }
})
```

```ts [v2]
export default defineNuxtConfig({
  site: {
    name: 'My App'
  }
})
```

::

更新配置时：

- 所有键都不再带 `site` 前缀
- `language` 配置已重命名为 `defaultLocale`

环境变量的行为没有变化。建议阅读 [站点配置如何工作](/docs/site-config/guides/how-it-works) 了解更高级的配置。

## 预渲染变更

在 v1 中，你必须预渲染所有页面，我们会修改你的 `nuxt.config` 以确保这一点发生。

在 v2 中，服务器可以在运行时生成所有内容，我们不再提供预渲染相关的改动。

如果想保留预渲染行为，可以把它加到 nuxt.config。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  nitro: {
    prerender: {
      crawlLinks: true,
      routes: [
        '/',
      ],
    },
  },
})
```

### Nuxt OG Image

从 v1 升级到 v2：

- [v2 发行说明](/docs/og-image/releases/v2)

我们从 `nuxt.config` 的 `ogImage` 中移除了以下选项：

- `host`、`siteUrl` - 详情见 [安装](/docs/og-image/getting-started/installation)。
- `forcePrerender` - 已移除（不再需要）
- `satoriProvider` - 已移除（改用 `runtimeSatori`）
- `browserProvider` - 已移除（改用 `runtimeBrowser`）
- `experimentalInlineWasm` - 我们移除了它；现在会根据环境自动处理
- `experimentalRuntimeBrowser` - 我们移除了它；现在会根据环境自动处理

`defineOgImage` 选项中以下选项已弃用：

- `static` - 改用 `cache`

如果你引用了旧的默认模板，需要更新它。

- `OgImageBasic` - 移除该属性，让系统自动选择回退模板

组合式 API 和组件：

- `defineOgImageStatic()`{lang="ts"} 已弃用，改用 `defineOgImage()`{lang="ts"}（默认行为是缓存）；如果你想写得更明确，可以使用 `defineOgImageCached()`{lang="ts"} 或 `<OgImageCached />`{lang="html"}
- `<OgImageStatic />`{lang="html"} 已弃用，改用 `<OgImage />`{lang="html"}
- `defineOgImageDynamic()`{lang="ts"} 已弃用，改用 `defineOgImageWithoutCache()`{lang="ts"}
- `<OgImageDynamic />`{lang="html"} 已弃用，改用 `<OgImageWithoutCache />`{lang="html"}

如果你之前使用运行时浏览器，现在需要手动选择加入，才能在生产环境中工作。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  ogImage: {
    runtimeBrowser: true
  }
})
```

::code-group

```vue [v1]
<script setup lang="ts">
defineOgImageStatic(
  { /* */ }
)
</script>
```

```vue [v2]
<script setup lang="ts">
defineOgImage(
  { /* */ }
)
</script>
```

::

### Nuxt SEO Utils

`nuxt-unhead` 模块已重命名为 `nuxt-seo-utils`。这是为了更好地反映模块范围。

从 v1 升级到 v3：

- [v2 发行说明](https://github.com/harlan-zw/nuxt-seo-utils/releases/tag/v2.0.0)

```diff [nuxt.config.ts]
export default defineNuxtConfig({
-  unhead: {

  }
})
```
